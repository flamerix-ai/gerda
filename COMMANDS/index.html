    Bridge command reference¶

    Every command the bridge answers — 112 of them. Send one with ./gerda ctl send <name> '<json args>' or the mc_send MCP tool; a running bot serves the same set as the describe command and the mc://api MCP resource. Where two layers declare one name, the container row wins, as in dispatch (harness/main.js#buildManifest).

    Arguments marked required must be present; the rest are optional. A command whose description starts with DIAG: is a diagnostic probe and is listed under Diagnostic instead of under its layer. The dispatch path behind the layers: IPC.md.

    Bridge¶

    harness/bridge.js — Answered by the TCP gateway itself, so they work while main.js is deaf or stale.

    Command Arguments Description
    bridge_diag — stable-layer health answered by bridge.js itself (service running-states + heartbeats + revs); works even when main is deaf/stale
    ping — connectivity test → pong, answered by bridge.js itself
    restart_service name string — service: main|worker|bridge (default main) restart a jsMacros service via ServiceManager, bypassing main — recovers a stale/deaf main that can't restart itself

    Container¶

    harness/main.js — The supervisor's own commands: diagnostics, worker lifecycle, eval, and the eyes/hands primitives of harness/screen.js.

    Command Arguments Description
    chat message string required send any text/command to chat — drive mod & Baritone commands (/home, /sethome, /back, /warp, /tp, #goto …) via one generic passthrough
    click i int — button index
    text string — label substring
    x int — GUI x = pixel/guiScale
    y int — GUI y = pixel/guiScale
    button int — 0=left 1=right    		 click: real Screen.mouseClicked at GUI coords (x,y = screenshot-pixel/guiScale; drives FTB/custom GUIs), or a button by i/text
    close_screen — close the open GUI screen
    describe — this manifest — meta + live worker commands
    diag — one-call topology/health: live handlers+ext, worker heartbeat age, per-file deploy drift (bootRev vs disk). Main-local — works when the worker is dead
    eval code string required sandboxed JS eval (World/Player only)
    get_logs n int — lines, default 100 max 500 tail the NDJSON journal
    get_state — pos/health/dim/tool/worker snapshot
    goto x int required
    y int required
    z int required    		 raw Baritone #goto x y z (movement primitive)
    halt — hard stop + #stop Baritone
    introspect filter string
    target string — 'screen' to dump open-screen/button methods    		 dump jsMacros method names (debug)
    inventory — FULL carry inventory: per-slot list + per-id totals (carry), hotbar detail, ore/tool summary
    jeval code string required PRIVILEGED raw eval — full jsMacros/Java scope (Java.type, Client, mod APIs); loopback only
    key key string required — e.g. key.inventory, key.drop
    hold bool
    release bool    		 press a named keybind
    keypress code int required
    scancode int
    mods int    		 raw GLFW key to the screen (Enter=257 Backspace=259 Esc=256)
    knowledge sig string — world signature; default = current world
    all bool — return every world section + the signature list    		 read world-scoped knowledge (waypoints/resources/stats) for the current or a given world signature
    knowledge_set sig string
    waypoints array
    resources array
    stats object    		 merge waypoints/resources/stats into world-scoped knowledge (read-modify-write; other worlds + unspecified sections untouched)
    latest_screenshot — path+mtime of newest screenshot PNG
    load code string required load a passive module (runs in parallel)
    poll_events since int — last seq seen (0/omitted = all currently buffered) drain the bounded event ring since a cursor → {events, seq}; pass the returned seq next time
    read_screen — open GUI: title + button widgets (text/pos/active)
    reload_ext path string — override ext file path
    code string — inline ext code instead of the file    		 re-eval ext.js (reloadable mod-API plugins: EMI/prospector/FTB) WITHOUT reloading main.js — ship new mod commands via sync + this
    reload_main delay int — ms before restart, default 1000 (lets the response flush first) restart the main supervisor service itself (re-reads main.js from disk; headless GUI-free reload). Use after editing main.js; ext.js uses reload_ext
    reload_worker name string
    delay int — ms between stop and start, default 1500    		 idempotent worker reload = halt+start as ONE off-thread command (never deaf-locks main like a blocking halt can). Prefer this over manual halt→start; scripts/ops/reload_worker.py drives it
    scan radius int
    scan_y_range int    		 read-only ore scan around player
    screenshot name string — filename (default ai_shot.png) native in-game screenshot (jsMacros Player.takeScreenshot → screenshots/ai_shot.png; works unfocused while rendering)
    scroll x int
    y int
    amount int — default -3 (down)    		 scroll the open screen at (x,y); amount +up/-down notches
    services — list registered jsMacros services
    start name string start the worker service (loads bundle)
    status — container + module status
    stop — graceful stop of the worker
    type text string required type text into the focused widget (click a search box first)

    Ext plugins¶

    harness/ext.js — Mod-API plugins, reloaded live with reload_ext.

    Command Arguments Description
    assign allowed object — {minX,maxX,minZ,maxZ} or null=whole world
    forbidden array — [{minX,maxX,minZ,maxZ}, …] peer claims to avoid
    claimedVeins array — [{x,z}, …] vein columns peers are drilling (drill skips near them)
    hazards array — [{kind,x,z}, …] fleet-union hazard columns (treated like own recorded hazards)    		 push a fleet assignment (hub→bot, fleet hub assignment): XZ region this bot may mine + peer-claimed regions/veins to avoid + fleet-shared hazards
    cam_aim yaw number required
    pitch number required
    roll number — dutch angle, degrees (vanilla has none)
    smooth number — per-frame ease 0..1 (1 = snap, 0.15 ≈ soft pan)    		 Hold the camera at an absolute yaw/pitch every FRAME (Forge ViewportEvent hook). Eases toward the angle by smooth; survives the player's own rotation.
    cam_free — Release the camera hook — vanilla/spectator control again. The listener stays registered but stops writing angles.
    cam_hud hide boolean — default true Hide/show the HUD on this client (vanilla F1 + the jsMacros overlay). Always hide before a take.
    cam_look_at x number required
    y number required
    z number required
    roll number
    smooth number    		 Aim the camera at a world point every FRAME. Poll it (~4 Hz) with a moving subject's position for a smooth tracking pan — the easing does the interpolation.
    cam_pose x number required
    y number required
    z number required
    yaw number
    pitch number
    spectator boolean — also /gamemode spectator @s    		 Place the CAMERA client (op) at x/y/z with an optional yaw/pitch, optionally switching to spectator. Vanilla /tp — camera client only, never a bot.
    cam_spectate target string — player name; omit to release POV shot: vanilla /spectate so the camera rides a bot's eyes (smooth, no code). Omit target to release.
    cam_state — Camera hook state: mode, registered?, eased angles, and the per-frame counter (must climb at FPS, not 20/s).
    count_item item string required — item id, e.g. minecraft:iron_ingot read-only: total count of an item id across the whole carry inventory (hotbar + main)
    drawer_deposit pos array required — [x,y,z] of the drawer block
    items array    		 string — only deposit these ids (whitelist)
    keep array
    emi_recipe item string required EMI: open recipe GUI for what CRAFTS this item
    emi_search text string required
    limit int    		 EMI item search (headless): set search text → return matching item ids as data
    emi_uses item string required EMI: open recipe GUI for where this item is USED
    go_base name string FTB Essentials /home — teleport to the bot's saved base home (default name 'base'). Fire-and-forget — verify the move.
    grid axis string — xz (top-down, default) | xy | zy (vertical profiles)
    radius int — in-plane half-size (default 8, max 20)
    y int — xz: the Y level (default bot feet)
    z int — xy: the fixed Z (default bot)
    x int — zy: the fixed X (default bot)
    h int — vertical: Y half-height (default = radius)    		 ASCII block-slice of the world (X-ray): axis xz=top-down (default), xy/zy=vertical profile; air=. ore=O bot=@, dynamic legend for the rest
    interact_entity uuid string — target entity uuid (wins over pos)
    pos array — [x,y,z] block cell — nearest matching entity within radius
    entity string — entity-type substring filter (default 'item_frame'; NOT type — that's the envelope field)
    radius number — pos search radius (default 2.0)
    item string — item id to hold + place (default: keep held)
    verify string — consumed | none (default: consumed if item given, else none)    		 right-click a held item onto an ENTITY (vanilla item frame / armor stand — unreachable via interact_place's block path). Target by uuid, or nearest type-matching entity near pos (type default item_frame). verify=consumed (held stack dropped) or none.
    interact_place pos array required — [x,y,z] of the target block
    item string — item id to hold + place (default: keep held)
    face string — up/down/north/south/east/west (default: toward the player)
    verify string — consumed | none (default: consumed if item given, else none)    		 right-click a held item onto a block face (item frame / display / pedestal / lever). Aims the face centre (default: side toward the player) + interactBlock; verify=consumed (a held stack dropped — frames/displays) or none (dispatch only). The headless primitive of the interact mission.
    jm_refresh — live-reload JourneyMap's waypoint list from disk (WaypointStore.reset) so bot-written waypoints appear without a relog
    journeymap_sync — mirror the bot's waypoints + discovered veins into JourneyMap as visible waypoints (writes journeymap/data/sp//waypoints/.json, JM's own id scheme) + live-refresh
    markers ore string — vein/ore kind filter
    near int
    sig string — world signature; default = current world    		 query accumulated ore markers (mc_world.json resources, current world) sorted by distance
    ore_registry namespace string — filter to one mod namespace (e.g. gtceu) LIVE ore-block ids from the Forge registry (forge:ores tag ∪ *_ore id scan) — the generator behind config/ores_live.json
    prospect want string
    keep_open bool    		 run HV prospector: hold→scan→wait→extract veins as data→cache→close; returns resources + nearest vein per ore
    prospector_status lowPct int — low-energy threshold %, default 15 read-only: hotbar prospector stored energy (charge/max/pct + low flag) — recharge before it dies
    quest_claim quest string required — 16-hex quest id whose rewards to claim MUTATING: claim ONLY the named quest's rewards (ClaimRewardMessage per reward). Never claims other quests' rewards
    quest_complete task string — 16-hex task id (submit just this task)
    quest string — 16-hex quest id (submit all its tasks)    		 MUTATING: submit FTB quest task(s) (SubmitTaskMessage). Item tasks need the item already in inventory (legal, not consumed when consume_items=false)
    quests chapter string — filter by chapter filename (e.g. 'genesis')
    quest string — filter to one quest by 16-hex id (case-insensitive)    		 read-only FTB Quests live status (completion/deps/unclaimed per quest+task) — the objective engine's FTB status feed
    read_chat lines int — max lines (default 20)
    filter string — case-insensitive substring filter    		 read recent received chat lines as data (newest first, optional substring filter)
    recipe item string required
    limit int — max recipes (default 5)
    craftOnly bool — only crafting-table ≤3×3 recipes (default true)
    alts bool — include per-cell ingredient alternatives (capped; default false — they explode for wood)    		 resolve craft recipe(s) for an item as DATA via EMI (grid + ingredients + output) — headless, pack-correct; feeds scripts/dev/resolve_craft_chain.py
    reflect expr string required — JS expr evaluated in ext scope, e.g. "Player.openInventory()"
    filter string — case-insensitive substring filter on member names OR their Mojang annotation (e.g. "Rot" finds m_146922_ →setYRot)
    sig bool — include param/return signatures (default true)
    fields bool — include public fields (default true)
    mojang bool — annotate SRG names (m_…/f_…) with Mojang names via srg_names.json (default true)
    depth int — recurse into member types this many levels (0-2, default 0)    		 reflect any expression's runtime class — method signatures, fields, optional recursion (API-exploration tool, generalizes introspect)
    rtp — FTB Essentials /rtp — random teleport
    sethome name string FTB Essentials /sethome [name] — set a home at the current position
    spawn — FTB Essentials /spawn — teleport to world spawn
    storage_add pos array required — [x,y,z] of the container block
    kind string — drawer|chest|barrel|container (auto for drawers)
    facing string — drawer face override: north|south|east|west    		 manually register one container in the storage network (auto-detects drawer kind/facing; pass kind/facing to override)
    storage_list — list the registered storage-network containers for the current world
    storage_remove pos array — [x,y,z] to remove
    all bool — clear the entire registry for this world    		 remove a container from the storage network by position (or all=true to clear the registry)
    storage_scan radius int — horizontal scan radius (default 6, max 16)
    height int — vertical scan range ± (default 4, max 8)    		 scan a cube around the bot for containers (drawers/chests/barrels) and register them in mc_world.json storages (drawer contents recorded live). Hybrid discovery — pair with storage_add/storage_remove
    tool_info slot int — hotbar index 0-8 (default: held) decode held/slot tool NBT → durability + AoE (GT.Behaviours) + GTCEu stats (GT.Tool) + electric charge
    tp_waypoint name string
    ore string
    x int
    y int
    z int    		 fast-teleport: {x,z[,y]} coords | {name} waypoint | {ore} nearest vein (vanilla /tp; veins land at current Y). Fire-and-forget — verify the move.
    unassign — clear this bot's fleet assignment (mine anywhere again)
    use_item item string — item id to equip first (else uses held)
    look_down number — pitch degrees (e.g. 80 to aim at the ground before placing)
    clicks int — how many short right-clicks (default 1)    		 equip an item to the hand and tap key.use (right-click); optional look_down pitch + repeat clicks
    warp name string required FTB Essentials /warp — fast travel to a named warp
    wp_add name string required
    x int required
    z int required
    y int
    kind string
    dim string    		 add a JourneyMap waypoint live via the native API (WaypointStore.add) — visible immediately, no file/reload. dim defaults to current, y to player Y, kind sets color
    wp_list — list JourneyMap waypoints live (from WaypointStore.getAll)
    wp_remove name string required remove JourneyMap waypoint(s) by name via the native API (WaypointStore.remove) — immediate

    Worker bundle¶

    src/bot/entry/worker-bundle.ts — Gerda Bot's own commands, answered by the kernel inside the loaded bundle.

    Command Arguments Description
    add_waypoint name string
    kind string
    x int
    y int
    z int    		 record a waypoint (at the player, or at x/y/z)
    continue — approve the pending plan step (alias: proceed)
    goto_waypoint name string — default: nearest vein send the bot to a known vein, then mine it
    metrics — write the telemetry .prom snapshot now + log its path
    mission_abort — stop the active mission → IDLE
    mission_start name string required
    params object    		 activate a mission by name (switchable at runtime, no reload)
    mission_status — log the active mission + phase
    missions — log the available mission names
    nav_engine engine string — default|astar|dstar|auto (omit → report current) set the navigator engine for production GOTO (no redeploy) — D* Lite only engages on filler-free legs
    pause — pause the bot → PAUSED
    plan_abort — abort the plan + active mission → IDLE
    plan_start name string required load + start a registered plan (the orchestrator chains its mission steps)
    plan_status — log the plan, cursor, status, blocked reason, active mission
    plans — log the available plan names
    proceed — approve the pending plan step (alias: continue)
    remove_waypoint name string required remove a waypoint by name
    resume — resume the bot from PAUSED
    run — flip the plan to auto and drain to completion (or until a guard blocks)
    save_now — flush persistence to disk
    select step string — step index or id (jump)
    mission string — run this mission ad-hoc
    params object    		 jump to a plan step, or run a single mission ad-hoc
    smoke eat bool — also dispatch one real bite (destructive) live facade smoke test (worker context): logs SMOKE per check + SMOKE_DONE
    step — advance exactly one plan step, then wait for approval again

    Diagnostic¶

    Probes for testing and debugging; most are idle/paused only.

    Command Layer Arguments Description
    greedy_drive worker x int required
    y int required
    z int required    		 per-tick greedy nav to x/y/z (continuous veto; safe live test) — idle/paused only
    greedy_drive_stop worker — clear the per-tick greedy target + release keys
    greedy_stop worker — release the greedy navigator's movement keys (abort)
    greedy_to worker x int required
    y int required
    z int required    		 drive one tick of the greedy navigator toward x/y/z — call repeatedly
    nav_trace worker tail int — return only the last N rows dump the un-sampled per-tick parkour trace of the last greedy_drive
    sensors worker items array — item ids to report stock for
    includeStorage boolean — also count the open container's storage slots (default carry only)    		 live read-out of the sustain-loop sensors — vein exhaustion + item stock (the cycle's guards)
    set_arrival worker dist number — e.g. 0.4 for exact-block runtime arrival tolerance for greedy_drive (≤0 clears → cfg.nav.gotoArrivalDist)
    set_dstar worker on bool — force the D* Lite incremental engine
    noFiller bool — strip bridge/pillar/mine so D* engages    		 per-drive engine override for greedy_drive A/B — D* Lite engine + strip filler moves
    set_timeout worker ticks number — e.g. 3000 (~150s) runtime timeout (ticks) for greedy_drive — raise for a long natural traverse (≤0 clears → cfg.nav.gotoTimeoutTicks)
    storage_probe worker x int required
    y int required
    z int required    		 read a placed container's contents from the worker thread (kind/facing/slots)
    trace worker on bool — omit → report current state toggle per-tick decision tracing (T:TICK lines in get_logs) without a reload
